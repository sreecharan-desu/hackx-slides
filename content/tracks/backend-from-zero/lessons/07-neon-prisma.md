# Neon + Prisma

Neon hosts Postgres. Prisma talks to it with typed TypeScript. You do not install a database on your laptop.

| Tool | Job |
| --- | --- |
| Neon | Cloud Postgres + a connection string |
| Prisma | Schema and queries in TypeScript |

## 1. Get a connection string

1. Open [console.neon.tech](https://console.neon.tech) and sign in
2. Click **Create project** (name it anything, region close to you)
3. Copy the connection string
4. Paste it into `.env`

```bash
DATABASE_URL="postgresql://USER:PASSWORD@HOST/neondb?sslmode=require"
```

Use the string labeled **Prisma** or **pooled** if Neon shows one. Never commit `.env`.

## 2. Init Prisma

```bash
npx prisma init
```

That drops three things: `prisma/schema.prisma`, a generated `prisma.config.ts` at the **repo root**, and it may rewrite `.env`. Keep your Neon URL.

Move the config under `src/` so it lives inside `rootDir` (otherwise `tsc` says the file is not under `rootDir`):

```bash
mv prisma.config.ts src/prisma.config.ts
```

## 3. Replace `src/prisma.config.ts`

The file Prisma writes uses `env("DATABASE_URL")` from `prisma/config`. That type-errors in this Prisma version. We replace the file. Paths below are written **from the repo root** (same as the default `./prisma.config.ts`), even after you move the file into `src/`.

```ts
import "dotenv/config";
// This file was generated by Prisma and assumes you have installed the following:
// npm install --save-dev prisma dotenv
import { defineConfig } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  earlyAccess: true,
});
```

`dotenv` is already in the project from bootstrap. `earlyAccess: true` is what makes Prisma 6.12 happy. Paths here are **from the repo root**, same as if the file had stayed at `./prisma.config.ts`. That is why we never pass `--config src/prisma.config.ts` — Prisma would resolve `schema` next to the config file and look for `src/prisma/schema.prisma`.

`DATABASE_URL` stays in `prisma/schema.prisma` (`url = env("DATABASE_URL")`). The CLI still loads `.env` from the repo root when you run `npx prisma db push` with no `--config`.

## 4. Generator output

Keep the top of `prisma/schema.prisma` like this so the client lands next to `db.ts`:

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

`prisma-client` (not `prisma-client-js`) + an explicit `output` is the current default. Next slide: models, `db push`, and the import path that actually compiles.
